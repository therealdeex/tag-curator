# Tag taxonomy review — 2026-09-07

Updated both `config/default-tag-rules.yaml` and the local
`stash-tag-curator-data/tag-rules.yml`. The two now have identical semantic
checksums, 1,476 mappings and 144 canonical labels. All 71 production
“kept-as-is” entries have decisions: **13 map, 58 hide**. Position variants
are hidden, following the user's explicit preference for a compact taxonomy.

Production was inspected read-only. No production dictionary edits, tag
creation, scene updates, cleanup or plugin jobs were performed.

## Evidence and scope

- The live GraphQL query returned Stash v0.31.1 and 982 tags, including their
  current attached-scene counts, names, aliases and descriptions.
- The production dictionary snapshot was generated on
  `2026-09-06T23:00:39.374747+00:00`. It reports 1,732 translated, 1,026 hidden,
  71 kept and 21 undecided entries. Its checksum is recorded in the patch.
- The local active file had 1,277 mappings, all matching corresponding bundled
  entries. The bundle had 1,377. Missing bundled decisions were added locally;
  derived settings, protections and legacy configuration were preserved.
- Production contains many additional decisions. The targeted patch preserves
  unrelated live entries; the local file is **not a replacement for the live
  dictionary**. Sanitized snapshots are not complete backups of active rules.

Counts in the decision CSVs describe provider-tag occurrences in the snapshot.
Counts in the inventory describe currently attached tags queried from Stash.
They measure different things and were captured at different times. Neither
can be summed to obtain distinct affected scenes. No per-scene dry run was
performed, so exact scene additions/removals remain to be previewed.

## Decisions

[Every kept tag](kept-as-is-decisions.csv) has its disposition, target, count
and rationale. [The targeted mapping changes](mapping-changes.csv) include
before/after production decisions. [The live inventory](live-tag-inventory.csv)
compares all 982 attached tag records with live and revised local mappings.

The main rule is that a source must support its destination. Examples:

| Source | Revised interpretation |
|---|---|
| Generic orgasm variants | Hide; retain control only for explicit edging/denial |
| Natural or augmented ass | Hide optional body details; never map to breast labels |
| Breast contact | Breast play; retain titjob for explicit act synonyms |
| Orgy/group sex | Orgy, distinct from many-on-one gangbang |
| Wife/husband/friends | Hide; no inferred sharing, cheating or real marriage |
| Impregnation | Fantasy premise, without asserting pregnancy or a cumshot |
| Interactive / VR | Separate format labels, independent of POV |
| Interview / pre-scene interview | One interview category |
| Photoshoot / modeling | One photoshoot category |
| Positions, props, expression and grooming details | Hide under the compact policy |

Explicit compound labels retain multiple outputs where justified, such as an
act plus POV or orgasm plus bondage. Cast and age remain performer-derived;
the approximate `young (22-30)` age mapping and inferred pair counts were
removed. Existing ignored tags were not generally reopened; the explicit local
CFNM/clothed-sex preference is preserved in the targeted patch.

The original 31 additions were trimmed to **14**. The complete
[category decisions](category-decisions.csv) explain which labels were kept
and which 17 were omitted. Retained categories cover breast play, facesitting,
orgy and impregnation premises, glory-hole setups, speech/food play, five
production formats and sheer/swimwear clothing. Optional body details,
generic orgasm, small narrative distinctions and minor production labels
are hidden. Composite mappings retain independently supported outputs: for
example, bound orgasm keeps bondage even though generic orgasm is omitted.

These are canonical definitions in local rules, not tags created in production.
The [refinement comparison](refinement-diff.md) was generated by the new
dictionary comparison command. [summary.json](summary.json) contains the final
counts. All existing axes remain supported; no position axis was introduced.

## Factual metadata boundaries

Removed [33 legacy metadata shortcuts](metadata-boundary-decisions.csv),
including raw `AGE: 22-30` becoming a female 23–29 bucket and `CAST: trans`
becoming a single transgender woman. Prefixes and old curated labels are not
evidence of exact ages, genders, ethnicity or participant counts.

| Information | Authority | Provider-tag decision |
|---|---|---|
| Age at scene date | Performer birth date plus scene date | Ignore age labels and legacy bucket guesses |
| Cast | Associated performer records and their gender fields | Ignore count and gender shortcuts |
| Demographics and measurements | Structured performer metadata | Ignore inferred demographic labels; no numerical measurements from tags |
| Era and studio | Scene date and studio relationship | No provider mappings into these computed axes |
| Narrative theme | Explicit provider premise | Preserve as a theme, not as a claim about real-world conduct |

`THEME: Older/younger` remains an age-contrast premise even when birth dates
are unknown. It does not produce AGE or CAST labels. Explicit cheating and
hotwife genre tags remain themes; wife/husband and other relationship roles
alone are hidden. Height descriptors no longer imply average body shape.

Unknown factual values remain unknown. Existing enrichment still depends on
the completeness and correctness of linked performer records: it cannot
discover an uncredited participant. The existing Married IRL enrichment
requires an explicitly attached performer tag; it does not establish that
the scene's performers are married to one another. Structured measurements
may describe a performer now rather than at filming; no historical precision
is inferred. Protected manual labels continue to be preserved.

These boundaries are enforced in the revised default/active mappings and
covered by regression tests. The generic editor still permits custom rules;
this is not a new global prohibition on operator customization.

## Remaining uncertainty

Eleven local mappings remain deferred with no speculative outputs:
`ass play`, `ass worship`, `ass fetish`, `spread ass`, `ass to other's ass`,
`gagging`, `fat pussy`, `pussy play`, `virtual sex`, `golden squirt` and
`private sex`. Broad source labels need provider-specific context to choose a
more specific act, format or theme safely.

Of the 21 undecided snapshot rows, 17 have concrete map/hide decisions, two
remain deferred and two have redacted source names. No rule was created for
the literal `[REDACTED]` placeholder. Provider-only and live-only decisions
outside the patch have not all undergone semantic review. Some existing
canonical tags may already have been attached through inaccurate historical
rules; inventory counts alone cannot identify which scenes need correction.

## Production application

[production-dictionary-patch.json](production-dictionary-patch.json) contains
265 targeted changes and 14 canonical additions in the existing
`RulesEditor.save_mapping` argument format. It includes the expected checksum
from the production snapshot. Use the existing editor's locking, validation,
backup and checksum checks when applying it. A checksum mismatch requires
review against fresh rules; do not replace the checksum merely to bypass it.

Do not copy the local active YAML over production: that would lose unrelated
live mappings. Saving dictionary changes and updating scene tags are separate
operations. After saving the patch, preview the affected scenes before running
Update Library. Generated dashboard assets and local snapshots were left as
historical outputs; regenerate them through the plugin after an actual save.

## Validation

Both local files pass the runtime structural and semantic validator. The
production patch also validates when applied through the editor's merge
helpers to the non-redacted live dictionary entries and canonical labels,
using local derived configuration. This checks the patch structure and output
references; it does not verify the full live YAML or its current checksum.
