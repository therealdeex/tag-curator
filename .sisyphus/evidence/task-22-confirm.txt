T22 — Destructive operation confirmation gate
=============================================

Scenario: Destructive confirm flow
Tool: Bash
Steps:
  - static review of ui/index.js: confirm modal gates runPluginTask for
    every destructive operation
  - python3 -m pytest tests/ui/test_route_static.py::test_destructive_ops_are_confirm_gated

Result: PASS

Mechanism:
  - OPERATIONS registry tags each entry with `destructive: true|false`.
  - OperationsPanel.openConfirm(op) is the ONLY click handler for operation
    buttons; it sets opToConfirm state, which renders ConfirmModal.
  - ConfirmModal renders the scope summary, an estimate (when available
    from dashboard totals), a danger alert, and a "Confirm destructive
    operation" button whose onClick is props.onConfirm.
  - props.onConfirm is wired to confirmAndDispatch() in OperationsPanel.
  - confirmAndDispatch() reads opToConfirm, optionally requires a run_id
    (Rollback), then calls jobState.dispatch(...).
  - jobState.dispatch() is the ONLY call site of the runPluginTask
    GraphQL mutation. There is no path from a button onClick to
    dispatch() that bypasses the confirm modal.

Destructive operations confirm-gated:
  - Full Library Rebuild
  - Process New and Unprocessed
  - Reprocess Stale
  - Enrich from Performer Metadata
  - Remove Unused Tags
  - Rollback a Run (also requires explicit run_id text input)

Non-destructive (no modal):
  - Dry-Run Full Library Rebuild (dry-run only)
  - Validate Rules (read-only)

Evidence:
  - ui/index.js OPERATIONS array lines 296-405
  - ui/index.js confirmAndDispatch() at line ~954
  - ui/index.js ConfirmModal component at line ~1063
  - test_destructive_ops_are_confirm_gated: PASS
